# Cartographer

Free, open-source D&D battlemap maker (React 19 + TypeScript + Vite + Tailwind, 2D canvas). Every push runs lint, build and the e2e suite in GitHub Actions (`.github/workflows/deploy.yml`) as a warning only: `main` deploys to GitHub Pages straight away, whatever they report: https://pannbiffen.github.io/cartographer/

Inspired by Dungeon Scrawl: match its features, never copy its code, art or assets. Over time it should become its own product.

## Commands
- `npm run dev`: dev server on :5173. If it ever serves a blank page after edits, restart it (stale transform cache).
- `npm run build`: type-check (`tsc -b`, including e2e) and build.
- `npm run lint`: oxlint, should report nothing.
- `npm run test:e2e`: Playwright tests in `e2e/` (own server on :5174, ~25s). Add or extend a spec for every fix or feature. Helpers in `e2e/helpers.ts` map grid cells to screen points using the canvas's `data-view` attribute, so they follow the current pan and zoom.
- Visual check: run a one-off Playwright script from the scratchpad (`import { chromium } from '<repo>/node_modules/playwright/index.mjs'`) against `npx vite --port 5175`, and look at the screenshot. Stop the server with `pkill -f "vite --port 517[5]"`; a plain pattern also matches, and kills, the shell running pkill.

## Code map
- `src/App.tsx`: map state, undo history (`modifyMap` with `coalesce` keys so one stroke/drag = one undo step), keyboard shortcuts, menu definitions, autosave. Anything that replaces the whole map (New, Open, My Maps, share links) goes through `confirmReplace` + `replaceMap`, which ask first while the map differs from `savedMap` (the last map saved to or opened from a file), unless `preferences.unsavedChanges` remembers an answer. A new shortcut goes in the keydown handler, the matching menu item's `shortcut` label (written `Ctrl+X`; `formatShortcut` in `src/core/keyboard.ts` shows ⌘/⌥ on a Mac) and the README table; Help > Keyboard Shortcuts (`ShortcutsDialog`) reads the menus, so a key with no menu item goes in its `CANVAS_SHORTCUTS` instead.
- `src/components/`: app chrome: `MenuBar` (menus are defined in `App.tsx`), `ContextMenu` (right-click/long-press/Shift+F10 menu on the map; `MapCanvas` reports the spot and object via `onOpenMenu`, `App.tsx` builds the items), `Toolbar`, `Toolbox`, `DockPanel` (right-hand panel: active tool, selection, levels and layers), `MapSettingsDrawer` (map-wide settings under the canvas, closed by default; e2e specs that use them call `openApp(page, { mapSettings: true })` so the map is framed above it), `Dialog` (shared modal shell, `wide` for two columns; closes on Escape or a click outside, keeps Tab inside and gives focus back on close; `autoFocus` a control to start there) used by every dialog. Shared tool list, theme names and button/field classes in `options.ts`; colour tokens (`bg-ui`, `border-ui-border`, ...) in `src/index.css`, light by default and overridden per `data-ui-theme`/`data-accent` on `<html>`; never hard-code chrome colours. Size chrome in rem (Tailwind defaults), not px, so the interface-size preference scales it.
- `src/core/preferences.ts`: per-user settings (also read by the pre-paint script in `index.html`). `src/core/storage.ts`: all localStorage access, keys prefixed `cartographer.`; go through it so "Reset all local data" clears new keys too. `src/core/library.ts`: My Maps, the maps kept in the browser (index + one key per map). `App.tsx` autosaves the open map into its entry (`mapId`); `replaceMap` flushes a pending autosave first, and a new or starter map (`pristineMap`) is stored only once changed.
- `src/core/viewport.ts`: zoom limits, `zoomAbout`, wheel zoom speed, map bounds and zoom-to-fit. Arrow-key panning is `src/canvas/useKeyboardPan.ts`; it pauses while a selection is being edited, when `App.tsx` nudges the object instead (`nudgeObject`).
- `src/core/newMap.ts`: blank maps and the new-map look kept in preferences. `src/core/presets.ts`: named looks (the same `NewMapDefaults` fields) kept in the browser and shared as files; anything read from a file or storage goes through its `cleanLook`, so a new look field needs adding there too. `src/core/share.ts`: share links (deflated map JSON in the `#map=1:` fragment).
- `src/canvas/MapCanvas.tsx`: pointer input, tools, previews. `drawMap` keeps the drawn map (layers, grid, lighting, the faint levels below) on a spare canvas, redrawn only when `mapData`, `levelsBelow`, the view or the canvas size change; hover and selection frames just blit it and draw overlays. Anything new that affects the map's look must be in that cache key. A spec counting draw calls must force a redraw (a short pan) as hovering no longer does.
- `src/core/renderers/mapRenderer.ts`: the single renderer used by canvas and all exports. Floor patterns in `floorRenderer.ts` (laid out in world space so cells join up; their random numbers wrap every 16 cells, so each is drawn once per zoom into a cached tile and filled from it; an 8-cell repeat is the fallback if zooming gets slow; a style may colour them, see `textureColors`/`propColor` in `src/core/theme.ts`, so pass the theme, not an ink colour); stipple and crosshatch hatching (`hatching.ts`) are one wide stroke along the walls painted from such a tile. `drawWithOpacity` (see-through layers, faint levels below and their lights, which `renderMap` gets as `lightsBelow` to draw over the darkness) shares scratch canvases, so wrap any compositing change in `save`/`restore`. The tile cache is `patternTiles.ts`; darkness and wall-shadowed lights in `lightingRenderer.ts`, with light sources (placed lights + torches, `mapLights`, which VTT export also reads; lava's edge glow comes separately from `lavaLights`) gathered by `src/core/lighting.ts`. Windows (`layer.windows`, edge objects like doors in `objects.ts`) let light through: per light and window, the shape seen with that edge cut out of the walls (`wallsWithGap`) beyond the plain one.
- `src/core/levels.ts` + `layers.ts`: a map (`MapData`) holds map-wide settings and `levels`, each with its own `layers` (bottom to top). `App.tsx` hands the canvas, panels and exports a `LevelMap` (`levelView`: the settings plus the active level's layers); `modifyMap` drafts are the whole `MapData`. Layer ids are unique across levels, so `withLayer(draft, id, ...)` finds a layer on any level; level-wide edits use `withLevel`. Tools use the active layer and skip hidden/locked ones. Loading goes through `normalizeLoadedMap`, which also upgrades version 2 (layers at the top level) and 1 (one layer's content at the top level) files.
- `src/core/objects.ts`: doors/windows/stairs/props/labels/lights: hit testing, selection (carries its `layerId`), edits. `App.tsx` keeps a `Selection[]` (the last one is what the panel edits); group edits go through the plural helpers (`moveObjects`, `nudgeObjects`, `copyObjects`/`placeCopies`, ...). Replace objects; never mutate them (history shares them). A door with `angle` sits along a wall off the grid lines (diagonal, curved, hex) and its (x, y) is its centre: read doors through `doorLine`/`sameDoorSpot`/`snapDoor` (`toolGeometry.ts`), not `orientation`; `doorWalls` (`region.ts`) lists the walls they snap to.
- `src/core/tools/toolGeometry.ts`: brush, tunnel and door-edge geometry.
- `src/core/geometry/region.ts`: free-form floor. A layer's `shapes` and `cuts` (polygons in grid units, via `polygon-clipping`) merge with its cells into one outline (`layerFloor`, cached) that walls, hatching, lighting (`combinedWalls`) and VTT use; cell-only layers skip it. Edit them only through `applyShape`/`uncutCells`/`eraseShapesInCells`, which keep shapes and cuts from overlapping, and replace the arrays rather than mutating them. Textures on free-form floor live in `floorAreas` (polygons by texture, set via `applyShape`/`paintArea`); they win over the per-cell `floors` beneath, and cells drawn later take their squares back. Liquids (`WaterStyle`: solid water, see-through water, lava) are each cells plus free-form areas (`water`/`waterAreas`, `clearWater`/`clearWaterAreas`, `lava`/`lavaAreas`; rivers from `src/core/geometry/river.ts`), merged into one shoreline per liquid by `layerWater` and never overlapping one another; change them only through `addWater`/`paintWaterCells`/`eraseWater`/`drainWater`/`setWaterStyleAt`, and add a new liquid to `KINDS` there. Wall-less ground texture (Paint Floor, roads) is `paint` cells plus `paintAreas` by texture, changed only through `paintCells`/`addPaint`/`erasePaint` and drawn first in each layer by `renderPaint`. `src/core/tools/fill.ts` has the fill tool (`roomAt`, the door-bounded room, shared by `fillRoom`/`floodRoom`/`drainRoom`) and `textureAt` (the texture at a point). `hex.ts`: hex grid maths; hex corners come from a shared lattice so neighbouring hexes merge exactly. On a hex grid tools work in whole hexes: props, lights, stairs and foliage keys sit at `hexSlot` (fractional x, y), drags and arrow keys move by `hexOffset`/`hexNudge`, and doors on hex sides carry a `length`.
- `src/core/geometry/walls.ts`: thin walls (`layer.walls`, one per grid or hex edge, `{x, y, dx, dy}` so object moves treat them like others): corner snapping, `edgePath` for strokes, and `thinWallSegments`, which `combinedWalls` adds so lighting and VTT see them. A door on a wall's edge opens it (`closedWalls`).
- Outdoor maps (`outdoor` + `ground` settings): `renderMapGround` lays the ground over the whole view under everything; the canvas draws it before the faint levels below and calls `renderMap` with `ground: false`.
- `src/core/export/`: PNG/WebP, tiled PDF, Universal VTT. `pdfExporter.ts` (jsPDF) is loaded with `import()` on first use; keep heavy, rarely used libraries out of the main bundle the same way.

## Workflow
- Work on a branch per batch (`fix/...`, `feat/...`). Make one commit per logical change with a `fix:`/`feat:`/`docs:`/`chore:` prefix. Ask before merging to `main` or pushing.
- Backlog is GitHub Issues (`gh issue list`). Put `Fixes #N` in commits. Every new issue gets a `model: opus` (complex or design-heavy) or `model: sonnet` (routine, well-scoped) label, a `priority: high`/`medium`/`low` label (the user may re-rank them; pick high-priority work first), plus `enhancement`/`bug`/`ui`/`pro-parity`/`chore` as fits.
- "Triage #N": rewrite the issue in the style of the others (a short summary, bullets with the files and functions involved, cross-links to related issues, a final `e2e:` bullet), give it a clear title and add the labels above. Read the relevant code first so the pointers are right; don't implement anything.
- Cartographer is in alpha: map format changes needn't keep older saved maps loading, so no version bumps or upgrade code in `normalizeLoadedMap` for new fields.
- Keep the README feature list and shortcut table in sync with the app.
- When a task is done, check whether it taught something a future session would need (a new module, convention or gotcha) and add it here in a line or two. Keep this file short: no history or per-feature notes, those belong in commits and issues.
